# Family convergence contract — KCode

KCode is the jcode-lineage primary subject. Its mature value is not preserving the current deep fork; it is preserving any accepted jcode-lineage capabilities that survive comparison with current jcode, modern Codex/HeliosCLI and the canonical shared harness.

## Rules
- shared harness semantics are not KCode-owned;
- prefer upstream contribution, external adapter or thin patch;
- daemon/session/client types map to shared ontology through adapters;
- KCode-specific product behavior requires a demonstrated role or irreducible semantic delta;
- HeliosLite is donor-only;
- segmentation with HeliosCLI requires a stable role boundary and measured value;
- convergence may retire KCode repository identity while retaining jcode as a supported/canonical client/runtime adapter.

## Current likely retained investigation areas
runtime/server identity; session/client surfaces; provider breadth; memory/compaction; swarm/sub-agent behavior; permissions; ForgeCode/HERDR adapters; native TUI performance; Windows/Pine integration; update/release provenance.

Each area receives RETAIN / UPSTREAM / ADAPTER / SHARED-HARNESS / SUPERSEDED / RETIRE only after semantic comparison.
