K-J06 parallel/isolated work: workspaces/worktrees -> multiple attempts -> scheduler/QoS -> evidence/selection.
K-J07 client interchange: CLI/TUI/API/HeliosLab consume same harness effort/event semantics.
K-J08 Windows/Pine: native POSIX-oriented workflow without WSL/PowerShell becoming required development substrate, where Pine contract is available.
K-J09 update/upstream coexistence: current jcode tracking/contribution + KCode overlay update -> migrations/provenance -> rollback.

Stage projections mature the same harness spine; no disposable MVP state model.
