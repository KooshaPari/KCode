# Mature product ontology — KCode / jcode-lineage client

KCode is a jcode-lineage CLI/runtime candidate and shared-harness consumer/reference implementation, not automatically the canonical generic harness.

Independent projections:
1. client UX: TUI/CLI/headless/session/config/provider/auth/diagnostics/update;
2. runtime: thread/turn/model/tool/context/memory/workspace/sandbox/events;
3. jcode-specific extension/adapters: provider runtimes, daemon/protocol, HERDR, Pine/Windows integration where justified;
4. shared harness integration: durable effort, policy, evidence/grader, scheduling/fleet, client-independent projection;
5. coding specialization: repository/edit/shell/test/git/search/LSP/MCP/browser;
6. operations: performance/QoS/security/provenance/coexistence/migrations;
7. verification: upstream parity/delta, conformance, negative controls, journeys, evidence identity.

Authority rule: jcode/KCode session state is runtime state, not automatically durable-effort or product-acceptance authority.
